Legend
  • green OK, red NOT_OK with a classified behavior, amber NOT_OK because the spec hit an error or did not run; hover a cell for the entitlement and the detail.
  • A cell reads verdict/license/behavior.
  • Verdict: OK when the behavior is the one the tier is entitled to (WORKS(PREM) for a feature the tier includes and for a limit, WORKS(OSS) for a feature it does not include and for a base row), NOT_OK otherwise. The run passes only when every cell is OK.
  • License, what the operator's license status (stunnerctl license) said: GRANTED lists the feature; DENIED was validated and does not list it; INVALID means the key was rejected, the license server unreachable, or the status unreadable (stunnerctl license failed); FREE means no key was given.
  • Behavior, what the spec saw: WORKS(PREM) is the licensed behavior, for a limit row the limit holding both ways (what it admits works, one more is refused); WORKS(OSS) the documented open-source behavior without the license; ERROR means the spec could not classify it (an error, a timeout, or neither behavior), the detail says what was seen; MISSING means the spec did not run or left no result.
  • The rows come in three kinds, named by their prefix: base- rows have no premium behavior, WORKS(OSS) is their OK, and base-license also checks the served features against the catalog; feature- rows follow the feature catalog of the STUNner release under test, the member and enterprise tiers and their debug twins get their catalog features (the retired KernelOffload is granted by no tier: the offload, like the SIP and SRT gateways, is a limit); limit- rows check the usage limits of the tier the dataplane reports, every tier is held to its own.
