Legend
  • green OK, red NOT_OK with a classified behavior, amber NOT_OK because the spec hit an error or did not run; hover a cell for the entitlement and the detail.
  • A cell reads verdict/license/behavior.
  • Verdict: OK when the behavior is the one the tier is entitled to (WORKS(PREM) for a feature the tier includes, WORKS(OSS) for one it does not), NOT_OK otherwise. The run passes only when every cell is OK.
  • License, what the operator's license status said: GRANTED lists the feature; DENIED was validated and does not list it; INVALID means the key was rejected or the license server unreachable; FREE means no key was given.
  • Behavior, what the spec saw: WORKS(PREM) is the licensed behavior; WORKS(OSS) the documented open-source behavior without the license; ERROR means the spec could not classify it (an error, a timeout, or neither behavior), the detail says what was seen; MISSING means the spec did not run or left no result.
  • Entitlements come from the feature catalog of the STUNner release under test: the member and enterprise tiers and their debug twins get their catalog features, free gets none; the base rows (the license check and the basic connectivity checks) have no premium behavior, WORKS(OSS) is their OK.
